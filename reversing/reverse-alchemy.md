# Reverse Alchemy

## 핵심 요약

바이너리는 입력 문자열의 인접 바이트를 XOR한 뒤 `65`를 더해 출력합니다. 출력값 자체는 무작위처럼 보이지만, 변환식이 선형적이므로 마지막 제약식에서 시작 바이트를 결정하고 전체 평문을 연쇄적으로 복원할 수 있습니다.

## 관찰과 모델링

평문을 `S`, 출력 문자열을 `T`, 길이를 `n`이라고 두면 분석한 변환식은 다음과 같습니다.

```text
T[i]   = 65 + (S[i] XOR S[i+1])        (0 ≤ i ≤ n-2)
T[n-1] = 65 + (T[0] XOR S[n-1])
```

첫 번째 식에서 `65`를 제거하면 다음 관계를 얻습니다.

```text
A[i] = T[i] - 65
S[i+1] = A[i] XOR S[i]
```

즉 `S[0]`만 알면 나머지 바이트를 순서대로 복원할 수 있습니다. 마지막 식은 그 시작점을 결정하는 추가 제약으로 사용했습니다.

## 복원 과정

1. 출력 문자열 `KNG]SHYTXBW{zT\NX^GBrsntHRXPw`를 바이트 배열로 변환했습니다.
2. 각 바이트에서 `65`를 빼 `A[i]`를 계산했습니다.
3. 마지막 제약식으로 `S[0]`을 결정했습니다.
4. `S[i+1] = A[i] XOR S[i]`를 반복해 전체 평문을 복원했습니다.
5. 결과가 출력 가능한 ASCII이며 플래그 형식과 일치하는지 확인했습니다.

여기서 ASCII 검증은 답을 찍어 맞히기 위한 수단이 아니라, 역연산 및 바이트 처리에 오류가 없는지 확인하는 독립적인 sanity check입니다.

## 결과

```text
flag{inverse_function_m@ster}
```

## 배운 점

인접 바이트를 섞는 연산도 XOR처럼 역연산 가능한 연산만 사용한다면 강한 암호가 아닙니다. 변환 코드를 그대로 따라가기보다, 먼저 수식으로 옮기고 미지수와 제약식의 수를 확인하는 편이 빠르고 안정적입니다.
