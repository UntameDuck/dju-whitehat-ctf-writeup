# Reverse Alchemy 2

## 핵심 요약

두 번째 문제는 인접 문자 XOR 뒤에 길이와 인덱스에 따른 연산을 추가했습니다. 겉보기에는 복잡해졌지만, 연산을 역순으로 제거하면 다시 인접 XOR 관계가 남습니다. 순환 XOR 구조에서 생기는 한 바이트의 자유도는 알려진 플래그 접두사 `FLAG{`로 결정했습니다.

## 분석 전략

암호화 과정이 여러 단계라면 복호화는 반드시 역순으로 수행해야 합니다.

```text
hex 출력
  → 인덱스·길이 기반 덧셈 제거
  → 길이 및 13*i 기반 XOR 제거
  → 인접 평문 바이트의 XOR 값 t[i] 복원
```

복원된 `t[i]`는 본질적으로 다음 관계를 가집니다.

```text
t[i] = s[i] XOR s[i+1]
```

이 관계만으로는 시작 바이트 하나가 자유 변수로 남습니다. 모든 평문 바이트에 동일한 상수를 XOR해도 인접 XOR 결과가 유지되기 때문입니다. 따라서 가능한 시작값을 순회하되, 다음 조건으로 해를 좁혔습니다.

- 출력이 사람이 읽을 수 있는 ASCII인가?
- 대회 플래그의 접두사 `FLAG{`와 일치하는가?
- 닫는 중괄호까지 전체 문자열이 자연스러운가?

## 입력과 결과

암호문:

```text
5E6B7A669B91C5C0AAD4E3ECC8341B0B372745837E7A58
```

복원된 플래그:

```text
FLAG{function_revers@l}
```

## 판단의 핵심

플래그 형식을 무작정 대입한 것이 아니라, 선형식이 남긴 정확히 하나의 자유도를 기지 평문으로 고정한 것입니다. 암호 구조 분석과 형식 검증이 서로 맞물려 유일한 가독 결과를 만들었기 때문에 최종 해로 판단할 수 있었습니다.
