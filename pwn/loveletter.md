# Loveletter

## 취약점 요약

사용자 입력을 작은따옴표로 감싸 `echo` 명령에 삽입한 뒤 `system()`으로 실행합니다. 개발자는 블랙리스트로 위험 문자열을 차단했지만, 셸 문법 자체를 무력화하지 못해 command injection이 가능합니다.

```sh
echo '%s' > letter.txt; echo '\n!'; cat letter.txt
```

## 사고 과정

1. 입력은 작은따옴표 안에 있지만, 입력값 자체의 `'`는 차단되지 않았습니다.
2. 따라서 공격자가 작은따옴표를 닫고 새로운 셸 구문을 주입할 수 있습니다.
3. 명령 치환 구문 `$()`도 차단되지 않았습니다.
4. `flag`, `txt`, `/` 같은 연속 문자열은 필터링되므로 파일명을 그대로 쓸 수는 없습니다.
5. POSIX 셸은 인접한 따옴표 조각을 하나의 단어로 결합합니다. 따라서 `f''l''a''g`는 필터 단계에서는 `flag`와 다르지만, 셸 평가 시에는 `flag`가 됩니다.

## 최종 페이로드

```sh
X'$(dd if=f''l''a''g status=none)'Y
```

`dd`를 선택한 이유는 차단 목록에 없으면서 파일 내용을 표준출력으로 보낼 수 있기 때문입니다. `status=none`은 전송 통계가 결과에 섞이지 않도록 합니다.

파일명이 `flag.txt`인 변형까지 고려한 페이로드는 다음과 같습니다.

```sh
X'$(dd if=f''l''a''g?''t''x''t status=none)'Y
```

## 공격 흐름

```bash
nc dju-ctf.com 9001
```

첫 입력에는 임의 문자열을 넣고, 두 번째 입력에 페이로드를 전달해 출력에서 플래그를 확인했습니다. 원문에는 플래그 값이 남아 있지 않습니다.

## 근본 원인과 대응

블랙리스트는 셸의 방대한 표현을 모두 차단할 수 없습니다. 입력을 셸 명령 문자열에 결합하지 말고, 필요한 동작을 언어의 파일 API로 구현해야 합니다. 외부 프로세스가 꼭 필요하다면 셸을 거치지 않는 인자 배열 방식과 엄격한 허용 목록을 사용해야 합니다.
