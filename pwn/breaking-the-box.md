# Breaking the Box

## 취약점 요약

프로그램은 사용자가 지정한 인덱스에 정수 값을 쓰지만 음수 범위를 검사하지 않습니다.

```c
*(int *)((char *)&v8 + 4 * index) = value;
```

조건 변수 `v5`를 `1234`로 만들면 `system("/bin/sh")`가 호출됩니다. 스택 배치를 이용해 음수 인덱스로 `v5`를 직접 덮었습니다.

## 오프셋 계산

`v8`보다 낮은 주소에 `v7`, `v6`, `v5`가 4바이트 단위로 배치되어 있습니다.

| index | 덮어쓰는 대상 |
|---:|---|
| `-1` | `v7` |
| `-2` | `v6` |
| `-3` | `v5` |

따라서 입력은 다음 두 값으로 끝납니다.

```text
index = -3
value = 1234
```

## 익스플로잇 흐름

1. 인덱스에 `-3`을 넣어 쓰기 대상을 `v5`로 이동시킵니다.
2. 값으로 `1234`를 입력합니다.
3. `if (v5 == 1234)` 조건이 참이 되어 셸이 실행됩니다.
4. 제한된 셸이라면 `PATH=/bin:/usr/bin:/usr/local/bin`을 복원하거나 `/bin/busybox`를 직접 사용합니다.

`cat`조차 사용할 수 없다면 셸 내장 기능으로 파일을 읽을 수 있습니다.

```sh
while IFS= read -r line; do echo "$line"; done < /flag
```

## 근본 원인

양의 상한만 검사하거나 인덱스를 전혀 검사하지 않으면 signed integer를 통해 배열 앞쪽의 메모리까지 쓸 수 있습니다. `0 <= index && index < length`를 모두 검증해야 하며, 계산 과정의 정수 오버플로우도 함께 고려해야 합니다.

원문에는 최종 플래그 값이 기록되어 있지 않습니다.
