# 사진 저장소

## 결과

```text
FLAG{4p4ch3_H4nd13r_M15c0nf1gur47i0n_RC3!}
```

## 확인된 취약점

1. `shell.php.png` 같은 이중 확장자를 허용했습니다.
2. 파일 앞부분의 PNG magic bytes만 확인하고 나머지 콘텐츠를 신뢰했습니다.
3. 업로드 디렉터리에 외부에서 직접 접근할 수 있었습니다.
4. Apache handler 설정 때문에 이미지 확장자가 붙은 파일 안의 PHP가 실행됐습니다.

## 공격 흐름

```text
PHP payload 작성
 → PNG signature를 앞에 추가
 → shell.php.png로 업로드
 → /uploads/의 파일에 직접 접근
 → PHP 실행 확인
 → 시스템 탐색 및 플래그 획득
```

파일명과 magic bytes 검사가 각각 존재해도, 저장 위치에서 스크립트 실행이 허용되면 두 검사를 우회한 파일이 곧바로 RCE로 이어질 수 있습니다. 업로드 보안은 검증뿐 아니라 저장·서빙·실행 정책을 하나의 체인으로 봐야 합니다.

## 대응

- 허용된 확장자 하나만 인정하고 서버가 새 파일명을 부여합니다.
- 디코더로 실제 이미지를 파싱하거나 재인코딩합니다.
- 업로드 파일을 웹 루트 밖에 저장합니다.
- 업로드 경로에서 PHP/CGI handler를 제거하고 실행 권한을 차단합니다.
- `Content-Type`, 확장자, signature를 함께 검사하되 어느 하나도 단독 보안 경계로 보지 않습니다.
