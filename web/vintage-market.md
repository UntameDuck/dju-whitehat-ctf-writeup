# 빈티지 마켓

> [!NOTE]
> 원문에는 공격 체인 요약만 남아 있어, 확인되지 않은 URL·파라미터·페이로드는 추가하지 않았습니다.

## 기록된 공격 체인

```text
LFI
 → 웹 서버 로그 파일 읽기
 → 로그에 실행 가능한 코드 주입(Log Poisoning)
 → 오염된 로그를 LFI로 include
 → Remote Code Execution
 → 플래그 획득
```

## 분석 논리

LFI가 단순 파일 읽기에 그치지 않고 RCE로 확장되는 조건은 두 가지입니다.

1. 공격자가 제어할 수 있는 문자열이 서버 로그에 기록된다.
2. 애플리케이션이 해당 로그를 텍스트 출력이 아니라 실행 가능한 파일로 include한다.

일반적인 검증 순서는 정상 파일 include로 경로 동작을 확인하고, 접근 로그 위치를 식별한 뒤, User-Agent 등 로그에 남는 헤더를 통해 코드 조각을 주입하고 로그 파일을 다시 include하는 것입니다.

## 대응

- 사용자 입력을 파일 경로로 직접 사용하지 않습니다.
- 파일 ID와 서버 내부 허용 목록을 매핑합니다.
- 웹 프로세스가 로그 파일을 읽거나 실행할 수 없도록 권한을 분리합니다.
- include 대상 디렉터리에서 스크립트 실행을 차단합니다.
- 경로 정규화 후 기준 디렉터리 밖으로 벗어나는지 검사합니다.

플래그 값과 구체적인 요청은 원문에 기록되어 있지 않습니다.
