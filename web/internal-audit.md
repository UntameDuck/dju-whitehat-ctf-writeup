# 내부 감사 시스템 침투 작전

> [!NOTE]
> 원문에는 단계별 제목만 남아 있어 사실로 확인할 수 있는 공격 체인만 정리했습니다.

## 공격 체인

```text
Path Traversal / LFI
 → 서버 파일 열람
 → SSH 키 추출
 → SSH 접속
 → SUID 바이너리 식별 및 악용
 → 권한 상승
 → 플래그 획득
```

## 단계별 판단

1. 애플리케이션 정찰에서 파일 경로를 받는 기능을 찾았습니다.
2. 경로 순회 입력으로 애플리케이션 루트 밖의 파일을 읽을 수 있는지 확인했습니다.
3. 읽기 권한이 있는 사용자 홈과 SSH 관련 파일을 조사해 인증 키를 확보했습니다.
4. 획득한 키로 시스템 계정에 접근했습니다.
5. SUID가 설정된 실행 파일을 열거하고, 권한 있는 동작으로 이어지는 바이너리를 악용해 권한을 상승했습니다.

## 문서화 한계

원문에는 대상 파라미터, 키 경로, 사용자명, SUID 바이너리, 명령어, 최종 플래그가 남아 있지 않습니다. 이 값을 추정해서 채우면 재현성이 오히려 떨어지므로 미기재 상태로 보존합니다.

## 대응

경로 허용 목록, 서비스 계정의 파일 권한 최소화, SSH 개인키 보호, 불필요한 SUID 제거, `nosuid` 마운트 옵션 및 정기적인 SUID 인벤토리 점검이 필요합니다.
