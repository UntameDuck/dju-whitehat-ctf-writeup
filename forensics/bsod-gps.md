# BSOD 이미지 속 좌표 추출

## 접근 판단

제공된 이미지는 Windows BSOD처럼 보였지만, “좌표”라는 단서는 픽셀 분석보다 EXIF GPS 메타데이터를 먼저 확인해야 한다는 신호였습니다. 스테가노그래피를 바로 시도하기 전에 비용이 낮고 설명력이 높은 메타데이터 가설부터 검증했습니다.

## EXIF 분석

Pillow의 `_getexif()` 또는 `exiftool`로 GPS 태그를 확인한 결과는 다음과 같습니다.

```text
Latitude:  N 37° 31' 9.84"
Longitude: E 126° 56' 26.88"
```

N/E는 양수, S/W는 음수로 처리합니다. DMS 좌표를 십진수로 변환하는 식은 다음과 같습니다.

```text
decimal = degree + minute / 60 + second / 3600
```

```text
latitude  = 37 + 31/60 + 9.84/3600   = 37.5194
longitude = 126 + 56/60 + 26.88/3600 = 126.9408
```

명령행에서는 다음처럼 교차 확인할 수 있습니다.

```bash
exiftool -GPS* challenge.jpg
```

## 검증

변환된 `37.5194, 126.9408`을 지도 서비스에 입력해 실제 지점으로 일관되게 매핑되는지 확인했습니다. 이 단계는 분·초를 잘못 더하거나 반구 부호를 반대로 적용한 오류를 잡는 독립 검증입니다.

## Flag

```text
flag{37.5194,126.9408}
```

## 분석 원칙

이미지 포렌식에서는 EXIF → 파일 구조 → 문자열 → 픽셀/채널 → 주파수 영역 순으로 탐색 범위를 넓히면 불필요한 분석을 줄일 수 있습니다.
